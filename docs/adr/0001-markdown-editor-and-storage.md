# ADR 0001：采用独立 Markdown 工作区与私有原文/标准 HTML 双存储

- 状态：Accepted；用户于 2026-11-04 明确接受本 ADR
- 日期：2026-11-04
- 关联：#1、#2
- 详细契约：[../architecture.md](../architecture.md)

## 背景

第一版既要提供连续 Markdown 写作，又不能绑定主题或破坏 Gutenberg/已有文章。若只保存渲染 HTML，用户会失去 Markdown 原文；若只保存 Markdown，停用插件后普通主题无法展示；若浏览器和服务器各自解析，预览、保存和安全结果可能不同。

## 决策

1. 使用 Gutenberg `registerPlugin` 入口和全屏独立工作区，不注册自定义区块，不在 `post_content` 写插件区块定界符。
2. 第一版只支持 post、WordPress >=6.4、PHP >=8.1。
3. Markdown 原文保存在 `_ume_markdown_source`，标准安全 HTML 保存在 `post_content`；格式、转换版本和内容/source hash 使用配套私有 meta。
4. 所有插件 meta 为 single、私有、不进入通用 REST，并启用 WordPress revisions。自定义 REST 按具体文章检查权限和 nonce。
5. 预览和保存共用服务端 `league/commonmark` + WordPress HTML/URL 白名单；客户端预览 HTML 不作为保存输入。
6. 保存通过专用 REST 接口，携带 base content hash 和 modified time；冲突返回 409，不自动覆盖。
7. 工作区打开期间锁定本插件对应的 Gutenberg save/autosave；保存成功后刷新编辑器，以服务端状态重建，而非手工双向同步区块。
8. 普通已有文章只有空内容或纯文本/Markdown 可直接导入；Gutenberg/HTML 不自动反转。原生保存造成内容 hash 变化时显示冲突。
9. 保存采用预校验、revision、旧值快照、写入后不变量校验和失败补偿；不宣称 WordPress post/postmeta 写入天然具备数据库事务。
10. 停用和卸载默认保留文章内容与插件 meta。

## 备选方案与否决理由

### 自定义 Markdown 区块

否决作为全局编辑模式。它会把 Markdown 文档耦合到区块定界符，并在混合区块、停用插件和旧内容转换时增加额外边界。未来可另行提案独立区块，但不改变本 ADR 的整篇文章工作区。

### 浏览器实时解析，服务器再次解析

否决双解析器。虽然减少预览请求，却会引入语法差异和两份安全配置。第一版接受防抖服务端预览的网络成本。

### 标准 Gutenberg 保存请求直接提交 HTML

否决信任浏览器 HTML。专用接口能从 source 重建 HTML，并统一执行权限、冲突和不变量检查。

### 自动 HTML/区块转 Markdown

否决。反向转换无法对所有区块、短代码、embed 和原始 HTML 保证无损；第一版选择显式提示和人工迁移。

### 切换时强制双向同步

否决。任意原生 HTML 与 Markdown 双向同步会制造隐性覆盖。第一版使用 hash 检测，冲突由用户决定。

### 数据库事务作为唯一保护

否决不现实的通用承诺。WordPress 站点存储引擎和插件钩子各异，因此同时保留 revision、快照、回读校验和补偿恢复，并注入失败测试。

## 后果

### 正面

- 主题无需适配，停用插件后 HTML 仍可展示。
- Markdown 原文、转换版本和内容一致性可追踪。
- 安全边界集中，测试可直接针对服务端转换管线。
- 不破坏原生区块格式，已有内容不会被打开编辑器动作改写。

### 成本与限制

- 实时预览需要已登录的 REST 请求，离线时预览不可用，但源码仍保留。
- 保存成功后的编辑器刷新会增加一次页面加载，因此打开工作区前要求原生改动已保存。
- 原生 Gutenberg 编辑与 Markdown 不是无损双向同步，冲突需要用户处理。
- 双存储需要严谨的一致性测试和恢复逻辑，不能假设多表写入原子完成。
- PHP 8.1 和 WordPress 6.4 以下站点不在第一版支持范围。

## 验证要求

- 解析与安全：恶意 HTML/URL、空输入、深嵌套、超限输入及 golden fixtures。
- 数据：新建、更新、重复保存、revision 恢复、字段不一致、停用和卸载。
- 故障：保存前失败、post 更新失败、meta 更新失败、回读校验失败和补偿失败。
- 并发：同秒不同内容、另一会话先保存、原生模式修改和冲突保留本地源码。
- 权限：跨用户读取/预览/保存、nonce 缺失、媒体无权限、公开 meta 不可见。
- 编辑器：原生 dirty 阻止打开、save/autosave 锁配对释放、成功后刷新、取消和失败不丢源码。
